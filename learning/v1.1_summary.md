# ElysianMonitor V1.1 - Learnings & Refinements

## 1. Goal
Refine the v1.0 release into a production-ready **v1.1.0** by addressing stability issues, improving UI polish, and enabling robust long-running operations.

## 2. Key Challenges & Learnings

### A. Process Resilience (The Watchdog Pattern)
**Issue**: 
Users reported that port forwarding would "stop after sometime".
**Learning**: 
Relying solely on `process.Start` is insufficient for long-running network tasks. `kubectl` connections can drop or be terminated by the cluster.
**Solution**:
Implemented an **Auto-Restart Loop** (Watchdog) in the `PortForwardService`.
- The service now monitors the process state.
- If the process exits unexpectedly, the service waits a grace period (3s) and automatically respawns the process.
- **Takeaway**: External process wrappers must always handle "unplanned exit" scenarios to be reliable.

### B. UI Virtualization & Jitter
**Issue**: 
Scrolling the Service List was "jumpy" or glitchy.
**Learning**: 
Avalonia's `DataGrid` virtualization engine relies on consistent row heights. If cell content (like a default `CheckBox` or `ToggleSwitch`) has a minimum height larger than the `RowHeight` (even by 1 pixel) or variable margins, it causes the virtualization calculation to thrash.
**Solution**:
Strictly enforced `MinHeight` and `Height` styles for all controls within the `DataGrid` to match the row settings (20px).

### C. Watch Stream Timeouts
**Issue**: 
"Long time opening data will not refresh."
**Learning**: 
Kubernetes API Watch streams (`WatchPodsAsync`) are not infinite. The server will eventually close the connection (timeout) or network blips occur.
**Solution**:
Wrapped the `Watch` logic in an outer `while (!cancellationToken.IsCancellationRequested)` loop.
- **Effect**: If the stream ends naturally or throws an exception, the loop catches it, pauses briefly, and reconnects.
- **Takeaway**: Never assume a network stream stays open forever. Always design for reconnection.

### D. Multi-Port Service Identity
**Issue**:
Excluding port 80 for a service also unintentionally excluded port 443.
**Learning**:
Using `Namespace/Service` as a unique key is flawed for services exposing multiple ports.
**Solution**:
Updated unique keys to composite format: `Namespace/Service:Port`.

## 3. Notable Features Added
1.  **Duration Tracking**: Real-time timer showing how long a port forward has been active.
2.  **Portable Publishing**: Created a standardized script (`publish-portable.ps1`) to leverage .NET's single-file publish capabilities (`-p:PublishSingleFile=true`).
3.  **Visual Polish**: Switched to a Blue theme and added a custom application icon.
